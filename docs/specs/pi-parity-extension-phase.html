Pi-Parity Extension Phase

pi-parity-extension-phase.md · created 2026-08-14 · updated 2026-08-15 · umer

A thin kernel plus plugins, like Pi: Herdr runs backend code, the phone only composes approved native surfaces. No downloaded mobile code.

Context

muxr discovers Herdr packages, validates hash-bound manifests, asks each device for approval, and composes approved contributions through generic slots. The original four milestones shipped. The 2026-08-15 leftover is the conversion from extension.* names: the shell still mounted every destination at /inbox and titled it Inbox, so a third-party tab could not look like its own surface.

1. Declarative screens

List, detail, metric, badge, progress, divider, empty, button, text, switch, and select nodes. Data and submission reuse plugin.call; session actions reuse plugin.invoke.

2. Package management

muxr plugin installs, lists, updates, and removes local, git, and npm packages. Every runtime mutation still ends in Herdr.

3. Reload + invalidation

A bounded Herdr catalog poll detects re-links and emits plugins.invalidated without a reconnect, filesystem watcher, or second runtime.

4. Attachment guardrails

Bounded healing, file, patch, inbox, and renderer caps keep large sessions interactive.

2026-08-15 leftover

The generic content mount is /plugin. Inbox remains a plugin that uses it. /inbox redirects. Leftover extension* identifiers in the mobile runtime are renamed. Decision 0005 notes that the wire shipped as plugin.*.

Authority model

package source
  → Herdr registry/runtime
  → host validation + manifest hash
  → per-device approval
  → /plugin mount or compiled native slot

source/authority change
  → new hash
  → stale approval rejected
  → surfaces removed until re-approved

Hard boundaries

  • No downloaded React, JavaScript UI, HTML, WebViews, SVG renderers, or native modules.
  • No new plugin.data request and no schema major bump.
  • No password or secret form fields; screen actions use bounded host RPC only.
  • No npm lifecycle scripts or dependency installation in package v1.
  • Write RPCs require idempotency; complete responses are capped before parsing and transport.
  • No second plugin registry or process runtime.
  • The shell names no product feature in the content mount.

Verification

  • Mobile typecheck and focused plugin/invalidation flows pass
  • A navigation destination opens /plugin with that plugin's own title
  • Inbox still appears as a plugin destination, not a shell tab named Inbox
  • Prior milestone checks remain the historical tested record
