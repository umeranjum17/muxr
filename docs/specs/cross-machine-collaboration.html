Let a person select trusted computers in mobile Settings, then let their local Herdr agents prompt, watch, and read one another through muxr without a coordinator, a CLI setup ceremony, or a second voice pipeline.

The decision

Settings owns authorization. The phone carries signed offers and sealed grants between already-paired computers, then leaves the runtime path. Each host connects directly as a capability-scoped client of its selected peers. Herdr stays local and the relay stays blind.

Default peer scope

  • List machines and agents
  • Read pane output
  • Read status
  • Watch completion
  • Send prompts

Deferred: start agents returns after Settings can approve an exact target-reported directory.

Not granted

  • Arbitrary shell
  • Raw Herdr CLI
  • Terminal takeover
  • Close or destructive actions
  • Worktree landing
  • Arbitrary plugin calls

Authorization ceremony

  1. peer.prepare creates a target-specific key and signed source descriptor.
  2. peer.authorize verifies the controlling phone and creates a capability-scoped peer device on the target.
  3. The target seals credential and grant material to the source peer key.
  4. peer.install forwards that opaque bundle to the source for verification and owner-only storage.
  5. peer.list and peer.revoke expose truth and security-first removal.

The phone may remember pending intent for retry. Hosts and target authority remain canonical.

No zombie prompts

The relay can buffer traffic to an offline host, so every peer mutation carries encrypted operationId and notValidAfter metadata. The target checks freshness before dispatch and persists a bounded receipt. Retries reuse one operation id. The UI says Sent only after the target replies.

Adversarial release hardening

  • Five-minute mutation validity, 64 receipts per device, and revocation outside attacker-controlled receipt admission.
  • A persisted authorization journal resumes authority issue, generic hosted pair-session claim and grant, relationship persistence, and local crypto activation.
  • Every new peer socket must answer a fresh correlated encrypted liveness request before mutations are released.
  • Malformed decrypted frames are rejected before host access.
  • Voice reconnect refreshes only the pinned machine's grant generation; pairing requires End voice and switch.
  • Voice exposes no raw Herdr CLI or close tool, and remote output is bounded and redacted before provider access.
  • Owner review reopened this work for directed watch settlement, per-stream broker capabilities, retryable recovery fencing, canonical mobile authority reconciliation, stable aliases, and focused runtime extraction.
  • Independent review reopened it again for active capability abort, exact private watch settlement, reconnect-safe semantic mutations, local-first revocation, alias churn, deep mobile intent normalization, and precise trusted-local-plugin documentation.

Settings experience

  • A separate Computer collaboration row shows Off, Setting up, Disconnecting, a computer count, or Needs attention only when repair is required.
  • The selection screen lists each paired computer's name, platform, online state, and checkbox.
  • A real Agent collaboration switch controls the safe read, status, watch, and prompt permission bundle.
  • Turning the switch on confirms and authorizes the selected computers; turning it off confirms and revokes peer access.
  • Each failure remains actionable: Update muxr, Computer unavailable, Pair again, or Repair needed. Connected appears only after every directed grant is active.
  • Pending setup or revocation exposes a contextual retry action instead of a generic confirmation button.
  • Starting agents stays explicitly unavailable until exact target-directory approval exists; no fake permission is rendered.
  • Machine detail shows which named computers collaborate.

Prompt flow

  1. A local agent loads the compact muxr skill and runs muxr peers list.
  2. Resolve a human machine and agent alias through the owner-only local broker.
  3. Require an authenticated live target.
  4. Send a fresh idempotent prompt operation.
  5. Register a completion watch and read recent output when settled.

Disconnect flow

  1. Disable the source edge locally.
  2. Revoke the target peer credential.
  3. Close live sockets.
  4. Delete the source bundle after confirmation.
  5. Keep partial cleanup visible until convergence.

Realtime voice

Voice remains one native streaming speech-to-speech session pinned to an explicit machine and session. Audio never fans out. When the user asks the voice host to work with another computer, host-owned constrained peer tools list, prompt, read, and watch the remote agent.

  • Target becomes { machineId, sessionId }.
  • Reconnect keeps the captured target, relay, plugin snapshot, and provider while refreshing that same machine's grant generation.
  • Changing the active computer requires End voice and switch.
  • Provider plugins receive no peer credentials or unrestricted remote CLI. The per-stream broker token is least-ambient routing for an approved voice child, not hostile same-user isolation; enabled backends remain trusted unsandboxed local code.
  • The overlay uses human copy such as Voice on Linux · working with Mac / iOS builder.

Implementation inside one PR

  1. Peer contracts, signed capabilities, persistence, issue, refresh, rotation, and revocation.
  2. Host outbound peer client and typed operations.
  3. Freshness and durable idempotency receipts.
  4. Settings authorization, convergence, repair, and disconnect.
  5. Machine-aware pinned voice targets.
  6. Constrained peer tools for the voice host.
  7. Hosted and self-hosted verification plus adversarial review.

What stays out

  • Central coordinator
  • Relay-side decrypted routing
  • Phone runtime proxy
  • Agent mailbox or message bus
  • Cross-machine terminal federation
  • Simultaneous voice streams
  • CLI-required pairing

Verification

  • Settings creates symmetric peer grants for two computers without CLI setup.
  • Peers keep working after the phone goes offline.
  • A peer lists, prompts, watches, and reads the other computer's agent.
  • Undeclared control, shell, destructive, takeover, and plugin operations fail closed.
  • Expired or retried prompts never execute late or twice.
  • Revocation closes sockets and prevents future tickets.
  • Offline setup and disconnect converge honestly.
  • Voice stays one pinned native stream while reaching an allowed remote agent.
  • Switching computers during voice requires explicit termination.
  • No internal ids, credentials, private paths, or raw output are shown or spoken.
  • Existing Herdr, pairing, plugin, voice, and relay isolation flows remain green.
