remote-relay-enrollment.md · created 2026-08-17 · updated 2026-08-20 · umer

One always-on VPS can route encrypted muxr traffic for several agent machines, without exporting relay-owner authority or changing the E2EE data plane.

Boundary

A relay URL is not authority. The VPS keeps the owner secret. Each agent machine generates keys locally and receives one revocable credential scoped to the machine slug derived by the relay from its signing public key.

On the VPS

  1. Choose HTTPS/WSS ingress and optional read-only web hosting.
  2. Review and install a supervised relay-only service.
  3. Create a five-minute, one-use machine enrollment.
  4. Manage machines by friendly name and list number.

On the agent machine

  1. Paste one enrollment string.
  2. Generate and prove possession of machine keys locally.
  3. Store only a machine-scoped credential.
  4. Start the Herdr host, then pair phone or browser.

Authority model

  • Enrollment claims are hashed at rest, rate-limited, one-use, and short-lived.
  • The proof signs the enrollment id, relay URL, and canonical signing public key.
  • Machine credentials can mint host tickets and administer pairing, devices, and grants only for their bound slug.
  • Device credentials remain client-only and machine-bound.
  • Machine revocation invalidates tickets and drops live peers for that slug only.
  • The relay continues to route ciphertext without machine data keys.

Short native pairing

Native pairing displays one relay-qualified value such as wss://relay.example?pair=7KDM4-QXP7N. QR and manual entry use the same value. The two-minute resolver stores only a code hash and code-encrypted payload, consumes it atomically, and removes the handoff after the device receives its grant.

Implementation order

  1. Split relay-owner and machine state.
  2. Add machine authority and enrollment persistence.
  3. Add owner create/list/revoke and public proof-of-possession claim.
  4. Bind tickets and every administration route to authenticated machine scope.
  5. Revalidate credentials on ticket consumption and peer lifetime.
  6. Add remote control URLs and relay-only/host-only services.
  7. Expose separate VPS and agent workflows in interactive muxr.
  8. Prove isolation with two machines and one shared relay.

Verification

  • Bad, expired, replayed, or concurrently claimed enrollments fail.
  • Machine A cannot mint, list, rotate, or revoke for machine B.
  • Revoking B drops B's live peers and unused tickets without touching A.
  • VPS relay and local host survive reboot independently.
  • Native QR and manual entry share a short two-minute code.
  • The flow test proves expiry, atomic consumption, deletion from main and backup state, and relay-blind pairing secrets.
  • The EAS Cloud Android 0.1.11 emulator build paired live through Tailscale and reached the connected Herd screen.
  • Read-only browser pairing works through public WSS.
  • Completion summaries expose URLs and health, never credentials, claims, keys, or internal ids.
  • The existing local self-host flow and full release suite remain green.
