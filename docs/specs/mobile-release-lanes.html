Proven mobile release lanes

mobile-release-lanes.md · created 2026-08-19 · updated 2026-08-20 · umer

Two deliberate buttons: one sends EAS Cloud builds to internal testers, the other promotes those exact binaries to production.

Context

Mobile delivery must not depend on a merge, a workstation, or a local native toolchain. GitHub Actions is the manual control plane and Expo performs signed builds in EAS Cloud.

Internal testing

  • Choose Android, iOS, or both from GitHub Actions.
  • Run the release gate before spending a cloud build.
  • Build in EAS Cloud with remote automatic build numbers.
  • Submit the newly created builds to Play Internal and TestFlight.
  • Wait for linked build and submission jobs, then record their exact identifiers.

Production

  • Use a separate manual workflow protected by the production environment.
  • Require the tested Android version code and iOS build number.
  • Promote existing store binaries without rebuilding.
  • Keep automatic public release disabled unless policy explicitly changes.

Revision

2026-08-20: Replace merge-triggered local EAS jobs with a manual GitHub workflow that builds and submits through EAS Cloud.
