Native voice transport

planned

native-voice-transport.md · created 2026-08-18 · updated 2026-08-18 · umer

Move the realtime audio pump out of the JavaScript thread into a kernel-owned native transport, with provider plugins minting short-lived session descriptors instead of relaying audio forever.

Why

Today every audio frame is base64 JSON across two WebSocket hops, a spawned plugin process, and an 8-slot native queue. The v0.1.5 fixes (wake/Wi-Fi locks, mic-as-activity, consecutive reconnect budgets) made this survivable; they cannot make it good. Screen-off audio still depends on the JS event loop, there is no jitter buffer, and backpressure drops are silent.

Architecture

  1. Plugin mints a session, not a stream. The provider plugin returns a bounded descriptor: transport, endpoint, short-lived token, rates, flags. Permanent credentials never leave the host.
  2. A native kernel owns the call. Microphone, encode, socket or WebRTC channel, adaptive jitter buffer, playback, reconnect, and foreground-service lifecycle live in Kotlin/Swift. JS receives state, transcript, and metrics events only.
  3. Direct when safe, gateway otherwise. Providers with ephemeral client credentials connect phone-to-provider directly; the rest terminate at a plugin gateway speaking the same wire format.

Public contract

realtime.session.open  → { transport, url, token, inputRate, outputRate, flags }
realtime.state         → connecting | connected | thinking | speaking | reconnecting | ended(reason)
realtime.transcript    → { role, text }
realtime.metrics       → { droppedIn, droppedOut, jitterMs, reconnects }

No provider names, models, or tool vocabularies cross the boundary. A replacement provider plugin emits the same shape; the app binary needs no provider branch.

Verification

  • Loopback fixture: connect, force a socket drop, reconnect, assert bounded drop counters and no queue-dump chop.
  • Ten-minute screen-off soak without audio gaps beyond the jitter budget.
  • The existing voice plugin lifecycle check stays green; provider policy unchanged.
