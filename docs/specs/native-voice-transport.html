native-voice-transport.md · created 2026-08-18 · updated 2026-08-28 · umer

Keep existing host-relayed PCM providers unchanged while adding a provider-neutral, mobile-owned WebRTC media path for Codex Voice.

Why

Today every audio frame is base64 JSON across two WebSocket hops, a spawned plugin process, and an 8-slot native queue. The v0.1.5 fixes (wake/Wi-Fi locks, mic-as-activity, consecutive reconnect budgets) made this survivable; they cannot make it good. Screen-off audio still depends on the JS event loop, there is no jitter buffer, and backpressure drops are silent.

Architecture

  1. Two transport kinds, one capability. Existing pcm-relay plugins keep provider sockets and bounded PCM. New webrtc plugins own only authenticated signaling and control.
  2. The mobile kernel owns WebRTC media. It starts the Android microphone foreground service first, then owns the peer, microphone track, remote playback track, app lifecycle, interruptions, and teardown.
  3. Credentials stay on the host. The phone exchanges bounded SDP through the existing encrypted plugin stream. The signaling plugin returns only the answer and never exposes OAuth, account ids, or private headers.

Public contract

realtime.ready           → existing PCM transport is ready
realtime.webrtc.start    → request a provider-neutral mobile offer
realtime.webrtc.offer    → bounded complete mobile SDP offer
realtime.webrtc.answer   → bounded provider SDP answer
realtime.state           → connecting | connected | thinking | speaking
realtime.transcript      → { role, text }

No provider name, model, credential, prompt, or private event vocabulary enters the kernel.

Verification

  • Kernel flow reaches WebRTC connected, receives transcript and playback-track events, then closes every track and peer.
  • Provider flow proves owner-only Codex OAuth, account binding, fixed OpenAI origins, bounded SDP, memory-only custody, and redacted failures.
  • Live subscription smoke proves both transcripts, inbound remote audio, clean stop, and no credential leakage.
  • All existing PCM provider checks remain green.
