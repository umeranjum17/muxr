# Status

Coding-agent usage and machine vitals.

- **Activity:** pinned ccusage 20.0.20 loads `daily --by-agent --sections daily,session --json --offline`. The screen shows seven local calendar days, including today and idle days, from one captured instant. OpenCode activity already includes its SQLite store; no separate token counter is used for Go.
- **OMP and Pi:** accounted from their own session transcripts (`<omp root>/agent/sessions`, `$PI_AGENT_DIR/sessions` or `~/.pi/agent/sessions`), streamed read-only in a bounded child that only ever reads recorded assistant usage and model names. A forked session copies its parent's messages, so records are deduplicated by their original message identity before aggregation; ccusage's own totals for these two agents are replaced. Tokens stay cache-inclusive as recorded, a recorded zero cost stays zero and a missing cost stays unknown rather than free. If the scan cannot finish inside its deadline the screen says the activity is unavailable; it never shows a stale or truncated total. It never launches OMP or Pi. Respects OMP/PI profile, PI_CONFIG_DIR and existing XDG data roots.
- **OpenCode:** its message database contributes last-consumption recency only; its tokens come from ccusage. Read with Node's SQLite reader or Python 3's standard library on older Node 22 installations; if neither is available, the screen names the missing runtime.
- **Plan limits:** Claude uses its fresh local status-line snapshot or Anthropic account endpoint; Codex uses its app-server and includes both primary and secondary windows. Providers muxr has no plan integration for say so (“Plan limits aren’t connected in muxr”) rather than claiming the plan does not exist. OpenCode Go uses the first-party `https://opencode.ai/zen/go/v1/usage` endpoint for rolling, weekly and monthly utilization. Only `opencode-go` API credentials are selected: valid `OPENCODE_AUTH_CONTENT` takes precedence over `$XDG_DATA_HOME/opencode/auth.json` (default `~/.local/share/opencode/auth.json`). Credentials never enter output or the output cache. Failed reads show unavailable, not zero.
- **Host boundary:** the installation-owned `plugins/private-contexts.json` recipe projects provider paths/profiles and only the intended Go credential onto private stdin for the exact canonical Usage script. The generic launcher has no provider-specific branches. Generic plugin environments stay closed; third-party plugins cannot receive these settings by claiming the Status id.
- **Recency:** tabs sort by recorded consumption timestamps, independent of token volume. ccusage supplies session `metadata.lastActivity` across its available history; OMP/Pi transcripts inside the reported window and OpenCode's message database provide last consumption. Providers without a known timestamp sort alphabetically after known ones. No file modification times are treated as usage.
- **Bounds:** ccusage 10s, Codex 8s, local collector child 5s (4s internal scan deadline), and selected Claude/Go request 5s. Backend aggregate reports may be up to 8 MiB; the displayed model contains only bounded provider/model labels, estimated costs, tokens, and quota windows. Prompts, project details and session identifiers stay out. Owner-only per-tab caches expire after one minute (Claude 15s) and never survive a local date change; failed activity/limit reads are not cached. A secret-free configuration/account fingerprint invalidates the same cache entry when profiles, locations, overrides or the active Go key change.
- **Vitals:** disk, memory, load, and uptime of the machine running your agents.
- **Removal:** `herdr plugin unlink muxr.status`.
