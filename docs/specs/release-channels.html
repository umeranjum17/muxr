One main branch, three distribution channels, and immutable artifacts. Release testing freezes one candidate while new work continues.

Full approved design and verification checklist · Specification board

Source is not deployment

Branches organize changes. Channels express stability. Environments select servers and state. A manifest binds all three to the exact bytes being tested.

Feature PR → main → dev builds ↘ release branch → beta → final candidate → stable main continues independently

npm channel contract

@dev follows green development commits. @beta follows release candidates. @latest advances only through approved promotion.

A beta version cannot be renamed into a final version. Build and test the final-version tarball before publishing its exact bytes.

A development app beside Stable

Native Android flavors and iOS schemes must agree with Expo configuration. Give development its own app identity, links, storage, and visible channel. Production candidates retain the permanent store identity so the tested build can be promoted without rebuilding.

iOS delivery remains disabled until its local Mac path is validated.

Local evidence, automated delivery

Keep normal build and security CI. Run emulator gates locally. Candidate manifests reference the exact local evidence; promotion checks artifact hashes, versions and eligibility.

No GitHub emulator workflow is added. A green dev build cannot change the stable npm tag, registry links or production service.

Implementation sequence

  1. Channel/version metadata and immutable publisher.
  2. Explicit updater channel selection and native build identities.
  3. Green-source nightly and candidate build workflows.
  4. Production promotion by recorded candidate identity.
  5. Existing flow validation, artifact evidence and documented external setup.

Verification remains open

  • Exercise dev → beta → final packaging, digest tamper rejection and dry promotion.
  • Prove updater channel isolation with the installed-package flow.
  • Compile and inspect both Android identities and preserve production pairing.
  • Validate workflows and relevant existing checks.
  • Report external publishing/store steps separately from local checks.

This spec becomes tested only after its stated verification passes. Publication is not inferred from generated workflow files.
