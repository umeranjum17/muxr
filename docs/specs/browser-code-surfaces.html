Browser and Code web surfaces

in progress

browser-code-surfaces.md · created 2026-09-09 · updated 2026-09-11 · umer

Browser stops being a Kitty picture in a terminal and becomes a real WebView surface, carried by the encrypted loopback tunnel muxr already ships. Slice 0 proved it on a real Android build and killed Code in the same run. Slice 1 hardened the wire; Slice 1b hardens the end of it that a phone actually exposes — because a loopback port is not private on Android and cookies ignore ports.

The decision

One compiled mobile Web Surface container. Browser is a real react-native-webview for HTTPS and tunneled host-local apps. Code was to be a pinned code-server over the same surface and is killed at Slice 0: normal finger selection cannot cross a line in Monaco on a phone. The agent-browser takeover survives only as a labeled use host browser session mode, with no new CDP or pixel scope. No Browser failure ever falls back to Kitty, and nothing replaces Code.

Context

Kitty graphics cannot give a phone real input, selection, accessibility, scrolling, uploads, or a software keyboard that behaves. It also spends a PTY and a graphics protocol on something the platform does natively. Almost all of the substrate already exists in this repo, which is why this is a reuse job rather than a new transport.

Product shape

Browser

  • Native bar: back, forward, reload/stop, visible origin, share, return to agent.
  • Native scrolling, zoom, selection, keyboard, accessibility, uploads, downloads.
  • HTTPS loads directly with phone-owned cookies; host-local apps load through the encrypted tunnel with same-origin WebSockets, SSE and HMR.
  • Host-profile sessions stay a separate, labeled takeover mode.
  • Unsupported schemes, file URLs, popups and silent external navigation fail closed.

Code — killed at Slice 0

The workbench loaded, saved host bytes exactly, searched, undid and survived offline. It still failed the approved product criterion on the device:

  • finger drag cannot extend a selection across lines, and long-press offers Monaco's menu rather than native handles;
  • the software keyboard stopped opening reliably for focused carets;
  • fixing either needs a Monaco or workbench fork, or an equivalent custom editing layer, which the boundary forbids.

No supervisor, no Code capability, no launcher, no key-emulation layer, no fallback. Editing on the phone stays with native Files, Changes and History.

First-class entry points only

There are no live users of the legacy Terminal Browser / Tode launcher packages, so nothing is migrated, aliased, or impersonated (removed 2026-09-11). The only entry points are the first-class muxr.browser and muxr.code plugins, their Tools entries, and the muxr browser|code|surface CLI. The Tools launch takes a declared Surface path with the originating agent context and creates no shell or terminal pane. Legacy identities appear nowhere in the kernel, the package, or the skill. New semantics are provider-neutral capabilities.

surface.browser.open surface.browser.control-host-session surface.code.open resolution: explicit selection -> saved selection -> sole enabled claimant missing or ambiguous -> fail closed, never a terminal fallback

Transport and security work the platform still needs

  1. Authenticated framing binding direction, connection id, flag and monotonic sequence to every frame including close.
  2. Backpressure: bounded connections and queues, pause/resume and drain, explicit close on overflow, never dropped TCP bytes.
  3. Endpoint leases instead of a caller-chosen port, bound to machine, device, surface kind, plugin snapshot, worktree and expiry.
  4. Loopback authentication with code-server auth on, credentials only through the encrypted control plane.
  5. Web isolation: no file access, no native bridge, no multiple windows, strict navigation, separate browser state. A stable port is not cookie isolation, because cookies ignore ports — so each endpoint gets a private numeric loopback address, and the surface is admitted by a per-attach credential rather than by possession of a port. Landed in Slice 1b.
  6. Lifecycle: close on unmount, logout, revocation and unrecoverable disconnect; reconnect with fresh keys; never stop user-owned dev servers.
  7. Authority: observe-only and browser grants cannot launch or control surfaces.

Slice 0 — the kill test (done)

A feasibility path, not a product. One developer-only route reaches one host loopback port through the existing tunnel and renders it as real DOM.

Shipped here

  • apps/mobile/sources/app/(app)/surface/web.tsx — developer-only Web Surface: attach, load, error, retry, back, forward, reload, deterministic detach.
  • Activation: a Developer group on the machine detail screen, shown only when the existing devModeEnabled local setting is on.
  • scripts/diagnostics/application/serveSurfaceFixture.mjs — loopback HTTP + WebSocket fixture that pushes live updates.
  • scripts/diagnostics/application/checkPreviewTunnel.mjs now also drives a real WebSocket upgrade and a server push through the encrypted device-side bridge.

Why the route takes no parameter

It accepts no URL and no port from navigation, so no page, link or plugin contribution can aim it. The port is typed by the device operator inside trusted muxr chrome, behind the same developer flag that already gates host pids and ports on that screen. Deleting one route, one settings group and one fixture removes the whole slice.

WebView posture

  • No onMessage and no injected JavaScript, so Android never attaches the ReactNativeWebView interface: remote pages get no native bridge.
  • File access, file-URL universal access, automatic windows and multiple windows are off.
  • originWhitelist is deliberately * so every navigation reaches the app's own handler. The library hands whitelist-rejected URLs to Linking.openURL, which is silent external navigation; failing closed in the app's own handler is stricter. Only the exact tunnel origin, plus about:blank for the workbench's own iframes, is allowed.
  • No credential in a URL, a log line or the surface chrome.

Stated limits of Slice 0

  • The device port is fresh on every attach, so nothing survives a reattach. Cookies ignore ports, so two host apps reached this way share the 127.0.0.1 jar. Ephemeral proof only.
  • code-server is started by hand: unsupervised, unleased, no credential plumbing.
  • Android only. iOS is untested and unclaimed.
  • No backpressure yet, as the existing ponytail: note in the host forwarder already records.

Slice 1 — transport hardening (done)

Slice 0 proved the path works. It did not make it safe to point at a real repository. This is what had to be true first.

Authenticated framing

The wire gains a version. v1 is the legacy takeover layout, byte for byte. v2 carries a version byte, connection id, flag and a strictly monotonic per-direction sequence in the header, and repeats all four inside the sealed body, close frames included. One shared codec in @muxr/crypto implements the rules for both ends.

v1 connId | flag | sealed(payload) v2 version | connId | flag | seq | sealed(direction|connId|flag|seq | payload) tampered / replayed / reordered / remapped / reflected -> refused before any upstream socket is opened or written -> the tunnel ends; nothing resynchronises

Endpoint leases

preview.attach no longer takes a caller-chosen port on the product path. The device asks for a lease; the host records machine, device, surface kind, access, provider, context, endpoint, the plugin catalog digest and an expiry, and resolves the endpoint from its own table. Access is explicit: developer is an operator typing a loopback port inside muxr's own chrome and stays a named diagnostic operation, while product binds the lease to its capability provider and worktree, the provider being an opaque id checked against the catalog that this kernel never names.

Standing is re-read, never remembered. A lease needs an explicitly live, unexpired control grant every time it is touched, because a removed grant leaves no authority entry behind and an absent entry is not permission; an authority read or a catalog read that fails counts as no, not as an empty table. Expiry, revocation, a changed snapshot, a provider that is gone and an unreadable catalog each close the live listener and its connections within about a second, and authority is re-read before every new upstream dial too. Ownership is claimed before the awaits and revalidated after them, so a release, an expiry or a retry mid-attach closes the loser's transport instead of orphaning it. A held tunnel that still passes every check is renewed rather than killed at its TTL, bounded by those same checks and by the device grant's own expiry; an abandoned lease still runs out.

Flow control

v2 runs on authenticated per-connection credits, both ways. Each end may have one window of payload outstanding per connection and stops reading its own socket when that runs out, and it hands the peer window back only from its own write's completion callback, never on the frame's arrival — crediting on arrival is the same as having no window, since the peer refills instantly and queues without bound in the receiving process. A close frame never destroys a socket that still owes it bytes, so a browser closing mid-upload still delivers a whole body. Credits travel through the same codec as everything else, so a forged, replayed or re-flagged one is refused, and they are clamped so one cannot push a peer past the ceiling. Credit and close frames cost no window, so control stays deliverable under pressure. Frames are bounded one chunk each way, and so is the inbound side: a peer that sends past the window it was granted ends the tunnel rather than queueing bytes nobody bounded.

Pausing the device's own WebView socket, which is what the bridge used to do when its response queue grew, throttles the wrong producer entirely and cannot slow a sending host. Connection counts stay bounded and the old queue ceilings remain as backstops. Nothing drops arbitrary TCP bytes: a closing connection drains what it was credited before saying goodbye, and past a ceiling something closes explicitly. Legacy takeover keeps v1 framing with no credits at all.

Lifecycle and authority

One idempotent owner on the device holds everything an attach opens. Relay close, relay error, host death, a bridge that fails its checks, a startup timeout, leaving the screen and the caller's own close all reach it, and the listener, the socket and the caller's notification each happen exactly once. Its handlers go on before startup rather than by it, because the old arrangement let the bridge's own onmessage replace them: remote death then tore nothing down, and the device kept a live loopback listener under a page that still believed it had a socket. Leaving mid-attach cancels through the same owner, and a bridge that finishes starting afterwards is closed rather than returned to nobody. A reattach mints a fresh key and a fresh sequence. Observe-only and peer grants could never reach preview.*, cannot hold a surface now, and a lease belongs to the device it was issued to.

How to exercise it

  1. On the machine: node scripts/diagnostics/application/serveSurfaceFixture.mjs, which prints its loopback port.
  2. For Code, by hand on a disposable repo: PASSWORD=<throwaway> npx code-server@4.136.2 --auth password --bind-addr 127.0.0.1:8080 /tmp/surface-scratch. The password stays in the environment and the login form, never in a URL, an argument or a log line.
  3. On the phone: turn on developer mode in Settings, open the machine from Home, then Developer → Web Surface.
  4. Enter the port. The fixture page renders, its WebSocket pill turns green, pushes keep arriving. For Code, enter the code-server port instead.
  5. Leaving the screen detaches. A new attach gets a new device port, which is exactly why nothing is kept between attaches.

Revision · 2026-09-10

Runtime QA on the first Slice 0 build failed closed with preview: relay ticket required on a valid hosted pairing. The shared preview attach helper read only the connection-settings token, which is empty in hosted mode because the scoped credential and its relay live on the Device grant. It now resolves the ticket input from that grant, refreshes it before use, and fails closed with an actionable message when the grant is missing, expired or for another computer. Local and self-host behavior is unchanged, and the resolution runs before preview.attach, so a ticketless device no longer leaves the host joined to an abandoned channel.

Revision · 2026-09-10 (return path)

The next device run paired and opened the listener, but the WebView reported net::ERR_EMPTY_RESPONSE: request bytes reached the fixture, response bytes never reached the phone. Two return-path defects in previewBridge.ts, both invisible to a Node stand-in. React Native defines no global Buffer, so connection.write(Buffer.from(...)) threw and the catch closed the connection with zero bytes; the bytes now go to react-native-tcp-socket as the Uint8Array it already accepts. And destroy() runs on the module's shared executor while writes run on the socket's own, so closing on the host's close frame dropped the response still queued; the socket is now destroyed from the last write's completion callback. Unreadable binary frames tear the bridge down rather than being skipped. Wire framing is unchanged.

Revision · 2026-09-10 (Slice 1 flow-control correction)

Review found the host half of the credit change never landed as written: deliver wrote without a completion callback and credited on the next line, so device→host credited on arrival — not a smaller window but no window, since the device refilled instantly and could queue without bound in the host process. It now credits from the write callback and counts writes in flight. The same audit found the symmetric truncation: a close frame ran drop(), destroying the socket and discarding whatever node still held, so a browser closing mid-upload truncated the request body. The host now drains accepted bytes first, as the device already did for responses. The device’s unsent backlog gained explicit per-connection and aggregate ceilings, because pause() there is asynchronous across the native bridge.

Revision · 2026-09-10 (Slice 1 corrections)

Independent architecture review and a signed-Android run found the first Slice 1 pass incomplete, with a device origin still accepting connections after relay and host death while the page reported the socket open. Five root causes, all fixed. Lease authority used “not recorded as view-only”, which reads a removed grant as permission; it now needs an explicitly live, unexpired control grant, and a failed authority or catalog read counts as no. Attach validated before its awaits and took ownership after them, so a release, expiry or retry mid-attach could orphan a tunnel; ownership is claimed first, revalidated last, and every rejected or superseded transport is closed. The device installed its relay close and error handlers only as startup rejecters and never reinstated them, so remote death tore nothing down; one idempotent owner now covers every ending. Mobile backpressure paused the WebView socket, which cannot slow a sending host; both ends now run authenticated credits tied to completed writes, bounded frames and bounded outstanding bytes each way, with control frames always deliverable. And a fixed ten-minute TTL killed live surfaces mid-read; a held lease that still passes every check is renewed instead. Legacy takeover keeps v1 untouched, and the Surface still fails closed when a host will not confirm v2.

Slice 1b — local admission and private origins, this slice

Slice 1 made the wire safe. It did not make the device end safe, and that is the half a phone actually exposes: Android says plainly that a loopback listener is reachable by other apps on the device, and cookies ignore ports. A tunnel ending at 127.0.0.1:<ephemeral> is a dev server behind no gate at all, and one cookie jar shared by every endpoint reached that way. Encryption between phone and host addresses neither.

isolated WebView http://127.a.b.c:PORT/ <- private per-endpoint origin | + HttpOnly SameSite=Strict cookie device loopback listener bound to that exact address, no fallback | authenticated v2 frames over the relay preview channel host admission gateway node http/ws, checks EVERY request and upgrade | only this dials upstream 127.0.0.1:<leased port> the registered dev server

A gateway, not a dial

attachPreview no longer dials the dev server. It dials a lease-owned HTTP/WebSocket gateway on this machine’s own loopback, and that gateway is the only thing that dials the registered endpoint. It is written on node’s own parser, because a hand-rolled header splitter in a security proxy is a request-smuggling bug waiting to happen: llhttp already refuses duplicate or conflicting Content-Length, Content-Length beside Transfer-Encoding, invalid chunking, obsolete folding and bare-LF delimiters, before a request object exists. The device bridge stays a byte bridge; there is no HTTP parser in React Native and there will not be one.

A credential, not a port

Compiled mobile mints an independent 256-bit admission credential per attach — independent of the frame key, because a value that unseals frames must never also be the value that opens the gateway — and sends it only inside the encrypted preview.attach request. It is installed before navigation as a host-only, HttpOnly, SameSite=Strict, Path=/ cookie in the WebView’s own store: the structured setter with no domain input, so native defaults it to the exact request host (effectively host-only for an IP literal, where RFC 6265bis allows no suffix domain-matching), and with the WebKit store selected on iOS, where setFromResponse hard-codes Foundation’s store and the WKWebView would never send what it installed. The write is read back from the same store before the surface navigates, because a store that refused it looks exactly like one that took it. No injected JavaScript, no onMessage, no ReactNativeWebView interface, and the credential never enters URL text, page JS, app chrome, diagnostics, logs or agent output.

What the gateway checks, on every request and every upgrade

CheckRule
CredentialExactly one reserved cookie, byte-equal name, constant-time value. Zero, two, a case variant, a __Host-/__Secure- prefix or a wrong value is a refusal, not a search.
AuthorityExactly one Host, equal to this surface’s authority. Node accepts a duplicate Host and keeps the first, so the count is taken on the raw headers.
OriginWhen present, equal to the surface origin exactly. An upgrade without one is refused.
TargetOrigin-form only, so an absolute-form request line whose authority disagrees with Host gets nowhere. CONNECT is destroyed.
BoundsHeader count and byte ceilings, a five-second header deadline, and a bounded number of sockets that have not yet produced an authenticated request.
ContinueExpect: 100-continue is relayed, never answered, so an unadmitted caller is never told to go ahead.
Upgradewebsocket or nothing, no pipelined bytes, and opaque duplex only after an upstream 101 whose Sec-WebSocket-Accept actually answers this client’s key.

What it rewrites, and what it refuses to

Only muxr’s reserved cookie is stripped; application cookies and Authorization are forwarded untouched. Host and an exactly-matching Origin are rewritten to the registered upstream, because that is what makes an unmodified dev server’s own CSRF and WebSocket checks pass — erasing them is what would make it unsafe. A Location naming the upstream’s own authority is translated back to the frontend’s; one naming any other loopback authority fails closed, because a dev server does not get to hand the phone a port nobody leased it. A CORS origin matching the upstream exactly becomes the frontend origin and never a wildcard. An upstream Set-Cookie for the reserved name is dropped, so nothing upstream can replace or clear the admission; a Domain naming the upstream host is dropped so the cookie survives host-only, and Path, Secure, HttpOnly and SameSite are the application’s and stay exactly as they were. Every admitted page response also carries the gateway’s own content policy: connect-src, worker-src, frame-src and form-action pinned to the exact origin ('self' covers scheme, host and port), with https:/wss: scheme sources for external resources and no plain-http:/ws: source anywhere — so script inside the surface cannot make a credentialed request to another port on its numeric host, while same-origin HMR/SSE and external HTTPS keep working and plain-HTTP cross-origin dependencies fail closed instead of loading silently. Upstream enforcing policies are kept alongside it (enforced policies intersect, so upstream cannot widen it); report-only policies and reporting headers/endpoints are dropped, since their endpoints are an off-origin channel of their own. Top-level navigation stays exact-origin in the app’s own handler. There is no HTML or JavaScript rewriting: the promise is unchanged, proxy-compatible dev servers, not transparency for an app that hardcodes its own absolute URLs.

A stable, isolated origin

preview.lease now returns an opaque fingerprint of the endpoint itself — a digest over machine, surface kind, access and either the port or the provider and context — plus the host-allocated private origin assignment for it: a numeric 127.a.b.c host with octets one and four inside 1..254, plus a stable port in 40000..59999. Numeric, because *.localhost resolution is not a portable assumption across WebView releases. Per-endpoint hostname, because cookies ignore ports and two endpoints on one hostname would share a jar, while localStorage, IndexedDB and service workers key on the full origin and separate too. Allocated and persisted by the host under its data directory (atomic 0600 writes, append-only, never reassigned while old state may survive): the first assignment keeps the legacy derived origin where it is free, so reattach and restart return to the same address, and a colliding endpoint is moved to a free hostname instead of sharing. Corrupted or unwritable state fails every surface closed. The device learns the assignment inside the encrypted lease result and binds it; the host pins the gateway’s Host/Origin checks to the lease’s stored assignment, so a caller cannot choose the origin its surface answers to and no device-supplied Host or origin is trusted.

Ownership before credentials, and after them

The device binds that exact address before the credential is installed and before anything navigates; a bind that does not take ends the attach with no fallback and no second address. Detach hands the tunnel to a retiring list, React unmounts the surface, and only then is the address released — a page still mounted can still issue a request, and releasing under it is how a credential reaches whatever binds next. The credential is cleared before the listener goes. One surface is open app-wide, because Android’s WebView cookie store belongs to the process rather than to a WebView and react-native-webview exposes no per-profile store; pretending port identity covers the rest is exactly the assumption this slice exists to remove. Authority still comes from the live lease, never from cookie lifetime.

Contract

preview.lease gains endpoint; preview.attach gains admission. Both are validated on both sides — shape-only for the credential, since nothing may branch on a secret — and a credential offered to the legacy port path is refused, because there is no gateway there to admit it to. Legacy takeover keeps v1 framing, port attachment and 127.0.0.1 binding untouched.

Residual risk, stated rather than hidden

  • Same-site is per host, not per port. http://127.a.b.c:PORT and http://127.a.b.c:9999 are the same site, so without a content policy script running inside the surface could make a credentialed request to another port of that address and hand the credential to a local listener. HttpOnly does not help: the page never reads the cookie, the browser attaches it. The gateway’s response policy now closes the practical channels — subresources, fetch, EventSource, workers, WebSockets, frames and forms to any plain-HTTP or plain-WebSocket off-origin target fail closed — and top-level navigation stays exact-origin in the app handler. What it cannot express is “this host, other port, over TLS”: https:/wss: sources necessarily also match this host over TLS, and no listener there can present a trusted certificate for a numeric 127/8 address, so in practice nothing answers to capture the credential. Peer-UID checks would close even that, and are unavailable: SO_PEERCRED is AF_UNIX-only and getConnectionOwnerUid is restricted. Per-attach rotation bounds the window to one surface lifetime.
  • A stable origin is a poisonable origin. Service workers, IndexedDB, localStorage and application cookies survive detach and reattach by design; a worker at / intercepts the next attach’s first navigation before a byte reaches the gateway. The real control is a per-endpoint WebView profile (androidx.webkit MULTI_PROFILE), which react-native-webview does not expose. An independent review argued for a fresh random origin per attach instead, which would close this and the point above at the cost of the persistence the approved architecture asks for; the stable-origin decision stands and this is its price.
  • The assignment is guessable, and pre-bindable. Machine id, kind, access and a conventional dev-server port are guessable. The v2 first assignment hashes through a v2 domain so a loaded v1 address cannot reappear, and every v1 hostname ever seen is a tombstone the allocator never serves again. Pre-binding a fresh address remains a fail-closed denial of that address, never credential sharing.
  • incognito on any other WebView in the app clears the process-wide cookie jar. The attachment preview sets it. The surface fails closed rather than running unadmitted — but it does fail.
  • iOS cannot bind this yet. Darwin binds only 127.0.0.1; any other loopback address returns EADDRNOTAVAIL, so the surface fails closed there, with no 127.0.0.1, wildcard, shared-store, DNS or random-port fallback — a bind that does not take ends the attach. The admission path no longer assumes Foundation either: install, read-back and clear all address the WebKit store the WKWebView reads. Still unproven on hardware; nothing about iOS is claimed until an owned Mac and iPhone run it.
  • Lease renewal is device liveness now. The holder timer never touches: only authenticated preview.renew exchanges (every 4 minutes while mounted, acknowledgement required) advance presence, so a blackholed device with a live relay socket runs out on its TTL.
  • Unauthenticated callers still cost tunnel slots. The gateway bounds concurrent unadmitted sockets and refuses fast, but the byte bridge cannot tell an admitted connection from a hostile one. That is denial of service, not admission.
